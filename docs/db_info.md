## Требования

Перед началом убедитесь, что у вас установлены следующие компоненты:

### Для Windows:

- **Docker Desktop** (с поддержкой WSL2).
- **PostgreSQL** (если не используете Docker).
- **Qt 5.15** или выше.
- **Компилятор MinGW или MSVC** (в зависимости от сборки).
- **CMake** (если используется для сборки проекта).

### Для Astra Linux 1.7:

- **Docker** (устанавливается через пакетный менеджер `apt`).
- **PostgreSQL** (если не используете Docker).
- **Qt 5.15** или выше.
- **Компилятор GCC 8.3 или выше**.
- **CMake** (если используется для сборки проекта).

## Разворачивание на Windows

### 1. Установка Docker Desktop

1. Скачайте и установите [Docker Desktop](https://www.docker.com/products/docker-desktop/).
2. Включите поддержку WSL2 в настройках Docker Desktop.
3. Проверьте, что Docker работает:
   ```bash
   docker --version
   ```

### 2. Сборка и запуск базы данных

1. Перейдите в папку с проектом:
   ```bash
   cd \path\to\vu_backend
   ```
2. Запустите Docker Compose:
   ```bash
   docker-compose up -d
   ```
3. Проверьте, что контейнеры запущены:
   ```bash
   docker ps
   ```

### 3. Сборка приложения

1. Убедитесь, что у вас установлен Qt и компилятор MinGW/MSVC.
2. Откройте проект в Qt Creator или используйте CMake:
   ```bash
   mkdir build
   cd build
   cmake .. -G "MinGW Makefiles"
   cmake --build .
   ```
3. Запустите приложение:
   ```bash
   ./vu_backend.exe
   ```

## Разворачивание на Astra Linux 1.7

### 1. Установка Docker

1. Установите Docker:
   ```bash
   sudo apt update
   sudo apt install -y docker.io
   ```
2. Убедитесь, что Docker установлен:
   ```bash
   docker --version
   ```

### 2. Сборка и запуск базы данных

1. Перейдите в папку с проектом:
   ```bash
   cd /path/to/vu_backend
   ```
2. Запустите Docker Compose:
   ```bash
   sudo docker-compose up -d
   ```
3. Проверьте, что контейнеры запущены:
   ```bash
   sudo docker ps
   ```

### 3. Сборка приложения

1. Убедитесь, что у вас установлен Qt и GCC:
   ```bash
   sudo apt install -y qt5-default g++ cmake
   ```
2. Скомпилируйте проект:
   ```bash
   mkdir build
   cd build
   cmake .. -G "Unix Makefiles"
   make
   ```
3. Запустите приложение:
   ```bash
   ./vu_backend
   ```

## Работа с бэкапами базы данных

### 1. Создание бэкапа

Для создания бэкапа базы данных используйте утилиту `pg_dump`:

```bash
pg_dump -U postgres -h localhost -p 5432 vu_backend > vu_backend_backup.sql
```

- `-U postgres` — пользователь базы данных.
- `-h localhost` — хост базы данных.
- `-p 5432` — порт базы данных.
- `vu_backend` — имя базы данных.
- `vu_backend_backup.sql` — имя файла бэкапа.

### 2. Восстановление из бэкапа

Для восстановления базы данных используйте утилиту `psql`:

```bash
psql -U postgres -h localhost -p 5432 vu_backend < vu_backend_backup.sql
```

### 3. Автоматизация бэкапов

Создайте cron-задачу для автоматического создания бэкапов (на Linux):

1. Откройте редактор cron:
   ```bash
   crontab -e
   ```
2. Добавьте задачу для ежедневного бэкапа:
   ```bash
   0 2 * * * pg_dump -U postgres -h localhost -p 5432 vu_backend > /path/to/backups/vu_backend_$(date +\%F).sql
   ```

## Рекомендации по поддержанию целостности базы данных

1. **Регулярные бэкапы**:
   - Настройте автоматическое создание бэкапов.
   - Храните бэкапы на удалённом сервере или в облаке.

2. **Мониторинг состояния базы данных**:
   - Используйте инструменты мониторинга, такие как `pgAdmin` или `Prometheus`.

3. **Проверка целостности данных**:
   - Регулярно проверяйте целостность данных с помощью SQL-запросов.
   - Используйте транзакции для критически важных операций.

4. **Обновление базы данных**:
   - Перед обновлением создавайте бэкап.
   - Тестируйте обновления на тестовой среде.

5. **Логирование ошибок**:
   - Настройте логирование ошибок PostgreSQL для анализа проблем.

## Примечания

- Для Windows используйте `Task Scheduler` для автоматизации бэкапов.
- Убедитесь, что доступ к базе данных защищён (используйте SSL и сложные пароли).
- В случае сбоя всегда проверяйте логи PostgreSQL для диагностики.

1. **Логирование**:
   - Все изменения в базе данных логируются для последующего аудита.

2. **Пакетная вставка**:
   - Используется транзакция для вставки всех сообщений из буфера за один раз.
   - Это значительно снижает нагрузку на базу данных.
  
		> Как работает:
   		> - Сообщения сначала добавляются в буфер в памяти.
   		> - Когда буфер достигает определённого размера (например, 100 сообщений), данные записываются в базу данных одним запросом.

3. **Асинхронная запись**:
   - Логгер работает в отдельном потоке, чтобы не блокировать основное приложение.

4. **Оптимизация PostgreSQL**:
   - Можно настроить параметры `work_mem`, `shared_buffers` и `wal_buffers` для повышения производительности.
